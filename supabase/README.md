# قاعدة البيانات — اقرأ ده قبل أي حاجة

## القاعدة الحقيقية مش موصوفة بالكامل هنا

مجلد `migrations/` فيه **10 ملفات** من أول إنشاء للقاعدة. بعدها اتعمل
عشرات التعديلات (جداول، أعمدة، سياسات حماية، محفّزات، دوال) **من محرر
SQL في Supabase مباشرة** — ومنها اللي مسجّل هنا في `sql/`، ومنها اللي
اتشغّل قبل ما نبدأ نسجّل.

**النتيجة العملية:**

- الملفات في `migrations/` **ما بتوصفش الوضع الحالي**. أي استنتاج عن
  «الجدول ده محمي ولا لأ» مبني عليها = استنتاج على معلومة قديمة.
- **مصدر الحقيقة الوحيد دلوقتي هو قاعدة البيانات نفسها.** تتقرا
  باستعلامات على `pg_policy` و`pg_trigger` و`information_schema`.
- إعادة بناء البيئة من الملفات دي هتنتج قاعدة **مختلفة** عن الإنتاج.

## المجلدات

| المجلد | إيه اللي فيه | يتشغّل؟ |
|---|---|---|
| `migrations/` | الإنشاء الأول، تاريخي | **لأ** |
| `sql/` | التعديلات اللي اتشغّلت على الإنتاج، بالترتيب | اتشغّلت بالفعل |

## سطور الحذف المعطّلة

ملفان (`05` و`08`) كان فيهم `DROP TABLE … CASCADE` في أولهم. تشغيلهم
بالغلط على الإنتاج كان هيمسح الحجوزات والمدربين والناشرين والمستحقات
وكل المرتبط بيهم. السطور دي **اتعطّلت بالتعليق**، فأسوأ نتيجة ممكنة
دلوقتي هي خطأ «الجدول موجود بالفعل» بدل ضياع بيانات.

## الخطوة الصح اللي لسه ما اتعملتش

تركيب أداة Supabase الرسمية وسحب شكل القاعدة الحقيقي:

```bash
supabase link --project-ref <معرّف-المشروع>
supabase db pull
```

ده بيولّد ملف ترحيل **مطابق للإنتاج**، وبيفضل مطابق مع كل تغيير جاي.
محتاج تثبيت الأداة وكلمة مرور القاعدة. لحد ما يتعمل، الملف ده هو
التحذير الوحيد اللي بيمنع الناس تصدّق المجلد القديم.
